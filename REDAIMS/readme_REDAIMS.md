# REDAIMS-R 铁路调度实验数据分析和信息管理系统

Rescheduling Experiment Data Analysis and Information Management System for Railways (REDAIMS-R)

面向铁路运行方案研究，管理 Excel 基本图与调度结果，逐步提供运行图绘制、人工编辑、统计对比和历史归档。总体规则见 [总体计划](planAI/Plan_WholeSystem.md)。

## 最新架构调整：基本图独立管理（2026-10-25）

基本图从 run 中剥离，使用独立 baseTT_no，四表格式不变。直接存储在所选类别下并自动物理绑定；子类别没有自己的基本图时，向上使用最近祖先图，称为回溯绑定，不存副本。研究员到批次六级均纳入存储类别，普通 run 仍是批次下的运行结果。

导入只检查目标类别本级是否已有物理图：有则提示“将覆盖xxx 已存储的基本图”并确认；无则正常导入，不覆盖祖先或下级自有图。编辑支持改变实际存储类别，预览原、新两侧继承变化；详情展示实际类别与完整路径，不再固定显示所属批次。

本轮已实现独立基本图、导入覆盖、回溯解析、位置编辑和显式旧图迁移入口。**已有用户数据不会自动迁移，请在页面核对后逐图转换**。完整规则、实施顺序和验收见 [基本图专项计划](planAI/plan_baseTT.md)；目标操作见 [导入与编辑指南](docs/base_import_guide.md)。编号规则、移动目标占用等边界见 [待定事项](planAI/代码开发待定事项.md)。

## 分类树与共用时刻表编辑（已实现）

分类树只在基本图实际存储的类别下显示一次，不再在子类别重复显示回溯图；业务继承仍有效。BaseTT/run 共用编辑页：顶部为真实直属类别与“编辑所属类别”类别树窗口，中部为车站/列车下拉复选，下部为可点击单元格编辑的到发表格，右上角提供“校验”“保存”。正常流程先校验当前修改再保存工作状态，筛选不丢草稿，保存不等于归档。编辑表格锁定首列和三行表头；支持两级列车显示控制、独立股道/SEQ 开关，以及新标签页编辑和 Dock 嵌回主界面。

完整界面、校验状态及验收见 [共用时刻表编辑计划](planAI/plan_timetable_editor.md)。分类树和共用编辑器已按此接通；普通run已支持单文件TTT导入、新建及确认覆盖，成功后自动进入同一编辑器，详见[run导入操作](docs/run_import_guide.md)。

## 当前已实现功能与兼容边界

- 免校验登录/退出，预留用户服务适配器；可折叠功能导航及 Light/Dark 主题。
- 六级分类管理、备注、完整路径显示、同父同名校验；类似 VS Code 的折叠树、创建子级联动及导航栏拖拽调宽。
- 分类管理“查看编辑 / 新建 / 删除 / 基本图”四页签，实际存储的基本图列为首项，回溯图只在详情显示来源。
- 分类递归删除及普通 run 的删除/未分组/转批次处理，事务与受管文件清理；跨路网移动暂阻止。
- 单文件四表预检、源坐标定位、日期与列车实例确认、持久导入任务、事务保存、来源副本与读取下载。
- 独立基本图使用 baseTT_no，六级类别均可存储；本级覆盖需确认，移动到占用类别阻止，删除有依赖图阻止。旧基本图通过显式迁移预览和备份转换。
- 独立只读 Excel 结构预览保留，结构通过不等于四表业务预检通过。
- 基本图/run单线路运行图，按线路站序和PASS→PASS等效间距作图；同基准日基本图叠加、车站/列车/时间筛选、缩放平移、高亮、悬停与只读草稿预览。

保存的是工作状态，不自动归档或备份。多文件/片段合并、预检在线修正、整车平移、SEQ 强制例外、experiment、统计与历史归档仍需后续开发。历史验证与状态见 [开发状态](docs/development_status.md)。

## 股道字段规范更新（2026-10-25）

NODE_INFO的DB_TRACKS/UB_TRACKS支持 `[10,11,12]`（无正线）或 `[5,6,7]/6`（兼用）：方括号内为该方向停站到发线，正线可省略，UP_TRACKS同义。数据库分开保存DB_STOP_TRACKS/DB_MAIN_TRACK、UB_STOP_TRACKS/UB_MAIN_TRACK；Excel导出重组为两列，不增加表单。总股道按实际基本图、线路、车站合并两方向到发线与正线并去重升序排列，不按1至N或跨线路推测。

车站股道运用图已接入：双击站名或在股道信息面板展开/收起，显示真实编号、正线与N+2条水平线，并按方向绘制到发边界和占用进路。支持基本图/run叠加、筛选、逆序、缩放平移及明细/日志；只读显示不改原_G和时刻。无正线的纯列表合法，库内正线字段为null；正线可兼作到发线并去重计数。旧计数不推测编号；新导入须按格式预检，格式升级前的暂存任务需重新预检。详见[字段定义](docs/数据字段定义.md)4.2.1及[运行图操作](docs/train_diagram_guide.md)。

## 基准日保存与Excel导出

编辑器可调整运行基准日，点击“保存”后先校验并确认日期变化，更新全部实际到发日期及列车基准日，保留跨日偏移。基本图和run均可导出xlsx，默认基本图四表、run仅TTT，也可自行勾选表单。

导出选择覆盖或另存：覆盖时重新选中磁盘源Excel，仅替换所选同名表单，保留其他表单；另存时指定新文件及位置。浏览器不支持直接写回时下载合并结果，由用户手动替换。导出使用已保存的完整数据，受页面筛选隐藏的数据仍包含在内。操作见 [导入与编辑指南](docs/base_import_guide.md)。更新代码后重启后端并刷新前端。

## 启动后端（项目根目录，PowerShell）

```powershell

依赖已安装时可跳过pip。接口文档 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)，健康检查 [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health)。请在项目根目录运行后端，避免从frontend执行导致找不到app。

config.yaml配置数据库、受管源文件、暂存和日志目录；相对路径相对于配置文件目录。默认数据库data/rail_data.duckdb。启动时创建缺少的表，不清空现有分类或自动导入样例。单机单进程使用，不支持多个服务进程同时写同一数据库。

## 新模型导入与分类管理流程

1. 选定实际存储类别，进入基本图导入；不再要求批次，也不另选绑定层级。
2. 选择四表 Excel、核对日期并预检；京沪样例的运行基准日为 2025-05-25。
3. 本级已有物理图时核对覆盖对象和影响并单独确认；本级没有图时按正常保存流程提交，自动物理绑定。
4. 基本图只在实际存储类别下作为第一项显示；子类不显示继承/回溯树项，但仍使用最近祖先图。基本图独立计数，普通 run 列表不混入基本图。
5. 基本图页显示实际存储类别/路径、当前查看类别、来源、日期、数量和受管源文件信息；“编辑所属类别”打开类别树，选择目标后先预览两侧影响再确认。

目标操作细节见 [导入指南](docs/base_import_guide.md)，存储设计见 [schema_design.md](docs/schema_design.md)，实际接口及旧接口边界见 [api_contract.md](docs/api_contract.md)。实际运行接口仍以 [openapi.json](docs/openapi.json) 为准。

源文件路径为受管副本路径，浏览器不提供上传前原电脑的完整路径。新业务中的物理存储指类别归属，磁盘仍可使用稳定 UUID 路径；移动类别不要求复制外部 Excel。

```

测试使用临时数据库与受管文件目录，不污染正式数据。前端目录运行npm run build进行类型检查和构建。当前代理环境默认dist/.vite-temp创建受限，验证使用：

```powershell

```

开发状态见docs/development_status.md，剩余业务事项见planAI/代码开发待定事项.md。显式旧图迁移前会备份数据库和受管源文件；一般编辑/覆盖不自动备份，历史归档与通用备份仍待实现。

时刻表提供车站上/下行排序、按选站到达/出发时刻的整组列车排序及“恢复原始顺序”。排序保留草稿和筛选，可在独立编辑页使用；重启后端、刷新前端后，按 [导入与编辑指南](docs/base_import_guide.md) 核对。自动化测试使用backend/tests/fixtures的固定工作簿，独立于用户正在维护的planAI样例。

时刻表显示补充：到达/出发列缩窄至约原宽的一半。筛选区在“车站选择”前增加线路选择（默认所有线路）；切换线路自动全选该线路车站，可在“车站选择”进一步微调。线路与勾选状态支持刷新和独立页/Dock恢复。原有车站上/下行、列车到达/出发排序与恢复原Excel顺序继续可用；筛选不影响完整草稿的校验、保存或导出范围。

列车到达/出发排序现采用三级取值：所选站目标时刻 → 该站另一到发时刻 → 未经过该站时沿所选线路双向查找最近可用站时刻。各级均按时刻插入同一序列；全部无时刻者置后。同刻先按级别、再按原Excel列序；隐藏站和当前草稿参与检索，切线/编辑失焦会更新排序。

## 运行图绘制（第一阶段已实现）

打开基本图或run时刻表，点击“查看运行图”，在绘图窗口选择线路。run可叠加实际回溯的有效基本图；支持时间范围、车站/列车勾选、站轴逆序、缩放平移、明细和日志。有效草稿可直接预览，保存仍在原时刻表编辑器完成。

第3级列车排序已更正为各线路的NODE_SEQ_OF_LINE邻站检索；车站行排序保持原LINE_IND/NODE_IND约定。完整操作和资料不足排查见[运行图操作指南](docs/train_diagram_guide.md)。多窗口比较、多run/跨日期比较、图上修改和图片/PDF导出仍为后续；多文件导入继续后置。

运行图内展开“车站股道信息与展开”，选择车站并点击“展开本站股道”；也可双击图中站名。占用绘图用于人工核对，自动股道冲突分析仍后续。

2026-10-25校验更正：_G按同一BaseTT中该站所有所属线路的上下行到发线/正线做OR判断，不检查股道编号顺序。列车SEQ可任意正整数起号、任意源表行序，同车仍须唯一连续；独立于_G/时刻的错误校验，保持源编号与行位置。

## 股道自动修复

基本图/run预检缺少_G列时按车次报错，可直接在预检结果打开“修复股道信息”，按列车、线路、UB/DB勾选并自动补列和分配，随后重新预检。共用时刻表编辑器也支持生成股道草稿，再校验保存。详细规则、占用区间边界与限制见[股道修复指南](docs/track_repair_guide.md)。

## 2026-10-26：小时线与多列车时刻对比

运行图整点小时线改为绿色2px实线加粗，独立于缩放后的分钟刻度。所选列车明细改为全部已选列车按车站对齐、分组并排显示，支持Ctrl增选和明细复选；基本图/run同车次分别列出，同站重复访问、原SEQ、空时刻和跨日日期均保留。点击“明细”加入当前对比并保留已有选择。

## 2026-10-26：通过列车股道标记与滚轮缩放

股道展开图对同刻到发的通过列车直接连接到发边界，并在指定股道上标点；缺失或不能定位的股道以所选线路两方向正线之间的红色三角形标记。鼠标滚轮以当前位置为中心同步缩放两轴，Ctrl+滚轮仅缩放时间轴，Shift+滚轮仅缩放车站轴。操作细节见[运行图指南](docs/train_diagram_guide.md)。

## 2026-10-26：SEQ缺列修复与整车平移

新增“修复SEQ信息”：缺列按车次报错、按有到发时刻的源行从1连续补号、自动重新预检；已有SEQ保留。同时缺G/SEQ先补SEQ再补G。共用时刻表新增“整车时间平移”，支持多列车、正负整数分钟/秒、完整运行线含隐藏站、草稿校验保存。 详见[SEQ修复](docs/sequence_repair_guide.md)与[整车平移](docs/time_shift_guide.md)。
