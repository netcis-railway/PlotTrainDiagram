# run 分析工作区

普通 run 下支持四类分析子节点：

| 类型 | 用途 | 保存入口 |
| --- | --- | --- |
| 视图 | run 运行图与绑定基本图对比 | 保存当前视图 |
| 求解日志 | TXT原文、搜索、求解器识别及Python求解进度图 | 导入日志；保存求解日志展示 |
| 延误预览 | 到达/出发延误矩阵与曲线 | 保存延误预览 |
| 指标分析 | 指标卡片、统计口径、到发演变曲线及热力图 | 保存指标分析 |

点击run的“查看运行图”或“延误预览”时，打开独立悬浮的run分析工作区，宽度为整个浏览器窗口；点击已保存分析子节点，也通过同一悬浮窗口回看。点击“返回时刻表”或按Esc关闭窗口，回到原主界面，保留时刻表筛选、表格状态及未保存草稿。主界面不嵌入分析内容。窗口有运行图分析、求解日志、延误预览三个独立的折叠小节，可同时展开多个。运行图初次打开使用自动范围，保存的视图恢复指定范围。原时刻表编辑器及其草稿保留。

## 操作按钮布局

run“查看编辑”页的“操作”行依次为“编辑所属类别、导入求解日志、修复股道信息、导出”。编辑框架在“run时刻表”标题上方单独排列“编辑时刻表、查看运行图、延误预览、指标分析、整车时间平移、在新标签中编辑”。“编辑时刻表”定位到编辑网格，“指标分析”直接进入指标页。独立标签页复用相同编辑框架，并保留“Dock · 嵌回主界面”入口。

主界面及独立标签页中打开的运行图分析窗口，均在标题上方排列“返回时刻表、指标分析、整车时间平移、保存当前视图、保存求解日志展示、保存延误预览”。平移按钮打开当前run的编辑草稿平移窗口，保留已读取的分析状态；回看保存节点时也连接当前run的编辑器。生成结果仍需回到时刻表核对、校验并保存。旧修订草稿、无时刻数据、读取中或已脱离当前窗口的编辑器禁用平移。具体规则见[时间平移指南](time_shift_guide.md)。

## run基本信息和小节备注

run“查看编辑”页提供run名称、run备注和“保存run基本信息”，独立标签页复用相同表单。保存后分类树名称同步更新，原run身份、编号、分类归属、列车和时刻数据保留；名称去首尾空白，同批次同编号的run不能重名。基本信息与时刻表单元格分别保存。

在运行图分析工作区的“运行图分析（视图）”“求解日志”“延误预览”中，各有独立的备注框和“保存本小节备注”。从run直接打开时，这些备注保存在run上，分别作为对应小节的父级备注，与run的总备注不同。

打开保存的视图、求解日志展示、延误预览、指标节点或导入的日志文件时，小节备注默认勾选“使用run的…备注”，显示父级对应小节内容。取消勾选后可填写本项目自己的备注并保存，覆盖父级显示；允许保存为空白。重新勾选并保存则恢复继承，之后重新打开会读取最新父级备注。子节点的覆盖只修改该节点，不回写run，也不改写已保存的分析配置或数据快照。

run总备注、三个父级小节备注、各子节点的小节覆盖分别持久化，每项最多20000字符。旧run总备注和父级小节备注为空，旧子节点默认继承，后端启动自动补充所需列。指标页已保存项目基本信息中，子节点类型和名称上下分两行排列，旁边显示总备注和保存按钮。

## 运行图列车显示与选择

顶部按钮行和“3. 延误预览”均提供“指标分析”，打开单run性能总览。指标页支持预设、配置侧栏、阈值、事件/单位/统计范围切换、热力表、时空热力图和二维/三维多车曲线；返回工作区保留原小节状态。“保存指标分析”创建独立的指标分析子节点，分类树以矩形框内的加粗大写P图标显示，点击直接打开指标页。旧版保存在延误预览类型中的指标快照仍可回看，另存时采用新的指标分析类型。详见[指标分析指南](performance_metrics_guide.md)。

车站菜单收窄为可并排容纳“全选车站 / 清空车站”的宽度；时间范围保留完整日期和秒，剩余宽度用于列车菜单。

列车菜单顶部为两行 N+3 列：只显示高亮列车按钮、基本图、各个 run、搜索框（N 为不同 run 数量）。第一行的基本图和 run 各有显示复选框及“全部 / 所选车次”单选项；第二行在对应来源下放置“全选 / 全不选”按钮。搜索列第二行留空，多 run 时按 run_no 升序扩展，并在空间不足时横向滚动。

- “全部”只控制绘图显示，不修改已勾选车次；切回“所选车次”恢复原选择。
- 取消来源显示也保留该来源勾选车次；基本图显示开关替代原“叠加有效基本图”。
- “只显示高亮列车”为一次性按钮：点击时把当时的高亮列车复制为勾选名单，并将各来源切换为“所选车次”；来源显示开关保持原设置。之后单击、Ctrl多选或取消高亮只改变高亮效果，点击按钮时的列车继续显示。再次点击按钮才会按新的高亮名单重新筛选。没有高亮列车时按钮禁用。
- “全选 / 全不选”只修改对应来源的勾选车次，包含搜索隐藏的行；人工勾选也可修改车次选择。
- 视图保存这些显示配置和全部已读取列车数据，包含尚未勾选的车次。空勾选名单在“全部”模式下有可见列车时也可保存。旧视图使用其原有快照数据；旧版持续高亮筛选会在回看时按保存的高亮名单转换为一次性勾选，之后高亮变化不再改变显示。

## 保存与恢复

点击“保存当前视图”“保存求解日志展示”“保存延误预览”或“保存指标分析”，在当前位置打开居中的保存浮窗。浮窗显示固定的子节点类型，可填写名称和备注；取消或按Esc关闭浮窗，原分析页保留滚动位置和筛选状态。保存期间禁止重复提交，失败提示直接显示在浮窗内，并保留输入。每次保存新建一个节点，同run、同类型不允许重名。节点记录整个已读取的分析工作区，而不只记录名称所指的小节：

- 三个小节各自展开/折叠状态；尚未读取的小节不生成数据快照，回看时首次展开读取当时工作数据。
- 运行图线路、基本图叠加、车站、基本图/run各自的列车与高亮、筛选搜索词及面板开关、坐标范围、站轴方向、股道展开、明细开关、图高及绘图数据/样式快照。
- 求解日志文件ID、编码、搜索词、自动换行、文本滚动位置及可视化组件的JSON配置。原始日志字节已作为run附件持久保存，节点引用该不可变附件。
- 延误车站、列车、高亮、筛选搜索词及面板开关、秒/分钟单位、坐标范围（内部以秒记录延误轴）、图高、表格滚动位置及计算结果快照。

打开已保存项目时，工作区和指标页顶部均显示子节点类型、名称和备注，可修改名称及备注后点击“保存名称和备注”。此操作更新原节点，保持ID、类型、创建时间和全部历史快照不变，分类树名称同步更新。旧视图也可编辑名称和备注；旧节点的备注默认为空。名称最多200字符，备注最多20000字符；后端启动时自动补充备注字段。

运行图和延误数据快照不随后续时刻表或绑定基本图变更而改变；保存节点不会提交时刻表草稿。运行图允许预览有效草稿，延误预览目前针对已保存的run。读取中的小节完成后才能保存。单个分析节点最多32MB（日志正文不重复放入节点），超限会提示而不部分保存。

导入的日志文件会直接显示为run下的“求解日志：文件名”，打开时使用默认文本配置；调整后可命名“保存求解日志展示”。之前的run_diagram_views旧视图继续显示并通过统一分析页回看，无需迁移。分类移动或取消分组保留节点和日志；未分组run也可从分类树展开回看；删除run同步删除其节点、旧视图和日志。

## 从分类树删除项目

在“实验”“求解日志”“延误预览”“指标分析”“视图”节点上右击，选择“删除”，在浮窗中确认所选项目名称和删除范围。取消或Esc关闭浮窗不执行删除；删除期间禁止重复提交，失败原因显示在浮窗内，节点保留。

- 删除保存的视图、求解日志展示、延误预览或指标分析，只移除该节点的配置、备注和数据快照，保留所属run、时刻表及日志附件。旧版独立视图也支持删除。
- 删除导入的求解日志文件会删除其附件记录。若仍有任一保存分析节点引用该日志，返回引用节点名称并阻止删除；先删除列出的保存节点，再删除日志文件。保存节点中的运行图、延误、指标等类型也可能保存日志展示配置。
- 在实验实体或run下的实验引用上删除，均删除整个实验及其成员关系，分类树中的实体和所有虚拟引用同步移除；成员run和时刻表保留。

删除当前选中项目后，分类树回到其所属run或原实验位置的上级条目。删除后同步更新本地列表，旧的读取响应不会重新添加节点；未分组run下的保存项目同样支持删除。

## 延误口径与交互

延误（秒）= run到发绝对时刻 − 绑定基本图到发绝对时刻，保留跨日累计秒及运行基准日差。正值为晚点，负值为早到/早发，0为正点，不把负值截为0。

按“车次+列车基准日”唯一匹配基本图列车，再按“车站身份+第几次经停”匹配到发事件。不同计划内部的train_id/event_id可不同；重复经停单独列行。基本图列车不唯一、缺少经停、SEQ重复或任一侧缺时刻时不虚构0，表格显示“—”及悬停原因，曲线在缺值处断开。无绑定基本图时显示原因。

表格为车站行、列车分组列，每车两列“到达延误/出发延误”，固定表头和首列。车站与列车可分别筛选，列车标题及曲线可切换高亮。到达曲线实线、出发曲线虚线，单位可切换秒/分钟。可输入站序/延误坐标上下限、调整图高或恢复自动范围。滚轮以鼠标为中心缩放，Ctrl仅站序轴、Shift仅延误轴。

## 求解日志可视化接入

默认可视化已接通Python作图：导入时按根目录solver_logs.json识别求解器并保存默认作图函数，日志页显示类型并调用相应代码。Gurobi原脚本保留plot_gurobi_progress.py文件名，放在backend/app/solver_visualizers/gurobi/，由adapter.py包装为网页PNG。界面支持切换已登记函数、图片缩放、下载和摘要；旧/歧义日志可手动指定类型或按当前规则重新识别。详细配置和扩展方式见[求解日志指南](solver_logs_guide.md)。

原frontend/src/solverLogVisualization.ts的registerSolverLogVisualizer(component)接口继续兼容，显式注册Vue组件时优先使用它；组件仍接收text、filename、state并通过update:state保存配置。未注册时使用默认Python作图界面，不再显示预留接口占位。PNG由真实日志和原作图代码生成；分析节点仅保存函数选择/缩放配置，回看时重新绘图。

UTF-8（含BOM）与GB18030/GBK可切换。编码不能严格解码时提示用户切换，不替换损坏字符后保存。搜索按文本筛选行并保留原行号，日志按纯文本渲染。原文件下载保留原始字节。

## Linux 保存视图报 JSON 解析错误

如果后端Traceback包含 `Required module 'pytz' failed to import` 和 `ModuleNotFoundError: No module named 'pytz'`，原因已经明确：运行后端的Python环境缺少pytz，DuckDB在将查询结果转换为Python时间对象时失败。本地Windows环境可能已通过其他依赖安装pytz，因此未暴露此问题。requirements.txt已显式声明该运行依赖。

在Linux项目根目录中使用后端实际的虚拟环境安装：

```bash
.venv/bin/python -m pip install "pytz>=2024.1"
.venv/bin/python -c "import sys, pytz, duckdb; print(sys.executable); print(pytz.__version__); print(duckdb.connect(':memory:').execute('SELECT current_timestamp').fetchone())"
```

确认安装成功且时间查询正常后，回到运行后端的tmux窗口，停止旧的uvicorn进程并按原启动命令重新启动，确保仍使用同一个 `.venv`。然后在网页重试保存。只在系统Python中安装、未给 `.venv` 安装，无法解决虚拟环境中的缺依赖问题。同步requirements.txt后也可通过 `.venv/bin/python -m pip install -r requirements.txt` 安装完整依赖。

“JSON.parse: unexpected character at line 1 column 1”表示收到的响应不能解析为JSON；仅凭这条信息不能判定保存失败的根因。保存运行图会上传完整绘图快照及已读取的延误数据，可能超过代理的请求体大小限制。Windows开发模式直连与Linux经反向代理访问可能因此表现不同。

前端现在会显示HTTP状态码、请求地址及响应类型，并保留后端原有JSON错误说明。HTML错误页、纯文本错误和意外空响应不会再掩盖成JSON解析异常，也不会作为保存成功处理或自动重试。

在浏览器F12的“网络 / Network”面板重新保存，检查 `POST /api/v1/runs/<run_id>/analysis-nodes`；旧版独立运行图窗口使用 `POST /api/v1/runs/<run_id>/diagram-views`。记录该请求的状态码、响应头Content-Type和响应内容：

| 响应 | 排查方向 |
| --- | --- |
| 413，响应为HTML或纯文本 | 检查Nginx或其他代理的请求体大小限制。 |
| 413，JSON说明快照超过32MB | 已到达Python接口，触发应用自身的快照上限；增大代理限制不会取消此上限。 |
| 404 / 405 | 核对Linux后端代码和运行进程是否更新，确认 `/api/` 路由代理到Python服务。 |
| 500 | 查看Python后端的完整异常日志，按具体异常检查数据库、目录权限等。 |
| 502 / 503 / 504 | 检查后端是否启动、代理目标端口及连接/超时日志。 |
| 200但响应是HTML | 请求可能落入前端静态页面、登录页或错误重写，需要修复API代理/重定向。 |

Nginx的 `client_max_body_size` 默认是 `1m`，超过时返回413；官方说明见 [Nginx请求体大小限制](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size)。如果确认是Nginx拒绝，在处理REDAIMS API的现有 `server` 或 `location /api/` 配置块中设置：

```nginx
client_max_body_size 40m;
```

40m为应用32MB快照上限及请求外层字段留出空间。若存在多层代理，需要核对实际拦截请求的那一层；更具体的location配置可能覆盖server设置。保存的快照包含当前已读取的完整绘图数据，单纯取消勾选车次不一定缩小请求。

在Linux服务器先检查配置：

```bash
sudo nginx -t
```

仅在检查成功后重新加载；使用systemd管理Nginx时执行：

```bash
sudo systemctl reload nginx
```

代理端口按实际部署保持配置。若配置 `/api/` 的 `proxy_pass`，需要保留后端所需的 `/api/v1/...` 路径；例如 `proxy_pass http://127.0.0.1:8000;` 保留请求路径，不能随意在该地址末尾增加 `/`。

后端连通性可在服务器本机检查（端口按实际部署修改）：

```bash
curl -i http://127.0.0.1:8000/api/v1/health
curl -i http://127.0.0.1:8000/api/v1/analysis/nodes
```

同步前端修改后，开发模式重启前端并刷新；静态部署重新执行 `npm run build` 并更新实际站点的dist文件。若仍保存失败，按新的HTTP状态及后端/代理日志继续定位，不能仅通过本地Windows保存成功确认Linux环境正常。

## 工作区导航与导出入口

基本图所选条目的“操作”行及右键菜单在“删除基本图”前提供“导出基本图和线路数据”。入口复用已有Excel导出窗口：把数据库四表更新到受管Excel工作副本，再导出该工作副本，保留其他线路表单。当前时刻表或四表存在未保存修改时，须先保存或放弃修改再导出。

分类树与右侧主内容各自滚动，滚动到边界也不会传递到另一侧或外层页面。项目分类的“新建 Experiment 实验”与“全部展开”“全部折叠”位于同一行，创建按钮仍为蓝色，字号与“刷新”一致。左侧导航新增“创建实验”，打开实验管理的新建表单并回到主内容顶部；新建实验的存放类别沿用当前所选分类。基本图导入、run导入和创建实验使用与分类树同一个图标组件。

求解日志导入和日志查看均可编辑目标函数最优值及求解时间，按字段标记“求解日志”或“人工填写”来源。详见[求解日志结果属性](solver_log_results_guide.md)。
