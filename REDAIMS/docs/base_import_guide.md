# 基本图导入、迁移与时刻表编辑指南

更新：2026-10-25。本页对应已实现的独立 BaseTT 代码。基本图不再作为 run 保存，不要求放在批次下。

## 1. 升级后第一次使用

重启后端并刷新前端页面。启动只创建缺少的新表，不会自动转换已有基本图。若以前导入过基本图，分类管理页会显示“旧基本图迁移”区域：旧图暂不混入新基本图树或普通 run 列表，也不会被当作新模型的有效基本图。

对每幅旧图点击选择存储类别，核对原批次、旧直接绑定、新位置和来源变化，确认后迁移。六级类别都可作为目标；目标已有物理图时需先处理，不能用迁移覆盖它。以前跨分支绑定的图不能继续随意绑定旁支：迁移预览会显示哪些分支失去来源，必要时为那些类别另行导入。

迁移提交前自动备份当前数据库及受管源文件目录，备份在数据库同级 `migration_backups/<唯一编号>/`，界面返回实际路径；保留旧 run_id 到新 base_tt_id/baseTT_no 的对照及旧记录快照。迁移保留原事件和来源，完成后移除旧基本图专用 run 和旧绑定。普通 run 不被转换。没有自动恢复按钮，回退需停止服务后按同一备份整体恢复数据库与源文件，不能混用新旧数据库和文件。

本次开发只在临时数据库执行迁移测试，未自动迁移用户工作数据。

## 2. 导入新的基本图

1. 在分类管理左侧选实际存储类别，点击“基本图”页签中的“在当前类别导入基本图”，或进入左侧“基本图导入 / 预览”。
2. 核对“存储类别”及完整路径；可通过类别树另选研究员、路网、场景、案例、算法或批次。基本图没有 run_no，也无需另选绑定层级。
3. 填名称，选 `.xlsx` 四表文件（单文件上限 32 MB），核对运行基准日和日期解释。京沪样例基准日使用 **2025-05-25**。TTT 表名留空自动识别，存在多个候选时明确指定。
4. 点击“四表预检”。预览源表、统计、列车实例基准日和具体问题；问题可按错误/警告筛选，带源坐标的问题可定位预览行。结构预览通过不等于业务预检通过。
5. 若本级已有基本图，页面显示“将覆盖 xxx 已存储的基本图”。核对原/新摘要及生效来源变化，勾选独立覆盖确认。覆盖按存储类别判断，名字不同也不能同级存两幅图。覆盖保留原 id/baseTT_no，替换四表与受管源文件，增加修订号。
6. 若本级只有回溯来源或下级自有图，正常导入本级新图，不覆盖祖先或下级图。勾选日期、列车基准日、适用警告及保存确认后提交。
7. 成功后自动物理绑定，生成独立 `BTT-<UUID>` 编号。树中基本图只出现在实际存储类别下，并作为第一项；子类无图时从最近祖先回溯，在详情显示来源，不重复生成树项。

预检不改正式工作数据。预检后类别、占用或版本发生变化，提交会拒绝并要求重新预检；真实格式/日期错误不能由覆盖确认绕过。页面“共 N 项阻断错误”是问题清单的汇总，不额外计作一项错误。失败保留原图；近期任务可恢复未提交预检或清理暂存。

## 3. NODE_INFO 股道格式

`DB_TRACKS`、`UB_TRACKS` 支持 `[10,11,12]`（无正线，全部为到发线）和 `[5,6,7]/6`（6号兼作正线和到发线）。正线可省略，库内保存null；正线号也可出现在到发线列表中，保留双重角色但只计一个物理股道。UP_TRACKS为别名，同时提供须到发线集合和正线号分别一致。编号须为正整数，单列表不允许重复；[]为明确无该方向股道，[]/9为仅有正线，空单元格为未知。裸数量、非整数或[10]/仍是格式错误，问题显示具体字段、源单元格和节点名称。

事件_G须为正整数或合法空值；非空时按本BaseTT中该站所有NODE_INFO所属线路的DB_TRACKS、UB_TRACKS及非空正线合并集合S做OR校验，命中任意一个即可，不要求同时属于每条线路。_G编号不检查递增、连续或与SEQ相等。两个方向各写 `[6,8,17]`，最终为三个编号，而非六条或 17 条。旧的整数数量不能推导真实编号；旧图迁移保留原值，编辑时会提示缺少列表，修改股道前应核对源表并重新导入正确列表。股道图已实现；绘图仍只使用所选线路的本站资源，不把S直接当作该线路的股道数。

## 4. 修改实际所属类别

打开基本图或 run 的时刻表，顶部显示实际直属类别和完整路径。点击“编辑所属类别”，在类别树中选择目标，然后核对原/新路径、生效来源变化并确认。

基本图可移到六级类别，身份和源文件路径保留，原/新两侧重新回溯；目标已有物理图时阻止移动。普通 run 只可移到批次，有时刻数据的 run 暂不开放跨路网转移。未保存的时刻修改须先保存或明确放弃，再改位置。移动基本图不移动其原类别下的子类别或 run。

## 5. 编辑到发时刻

1. 打开基本图页或普通 run 详情；核对顶部对象、基准日与真实直属类别。
2. 展开“车站选择”和“列车选择”，搜索并勾选所需项。表格以车站为行、列车为列组，默认显示到达/出发；可分别勾选“显示股道”和“显示SEQ”。“未经过”不提供编辑入口；已有访问的空到发可编辑。
3. 点击单元格输入。跨日使用 `25:10:00` 等累计小时，或 `2025-05-26 01:10:00` 完整日期时刻；不要把次日误写成当天 `01:10:00`。修改格有标记，原值可查看提示。
4. 点击表格右上角“校验”。校验针对完整对象加全部修改，包含被筛选隐藏的草稿，只读检查，不写正式数据。修正错误后重新校验；再次输入会使旧结果失效。
5. 无阻断错误后，核对适用警告和列车基准日变化，再点“保存”。成功保存工作状态，不改原 Excel，不自动归档；基本图修改不会反向重写普通 run 的到发时刻。

草稿按对象暂存于当前浏览器页签，切换筛选不会丢失。刷新恢复的草稿若基于旧版本，需核对当前原值并重新校验；保存冲突时保留草稿。关闭页签不承诺恢复，浏览器暂存不是正式保存或历史备份。

普通结果导入仍待开发；共用 run 编辑接口及页面已接通，但只有具备正式事件和基准日的 run 才有可编辑数据。未分组 run 的重新归类仍受已有跨路网映射限制。

## 6. 删除与验证范围

基本图独立删除需预览和确认；有后代类别或 run 仍依赖它时阻止删除。删除分类前须先移动或单独处置其中的物理基本图，不能把它当作未分组 run。旧基本图也须先迁移，避免丢失旧绑定与来源。

建议依次核对：祖先图只显示一次 → 子类回溯 → 子类另导入自有图 → 同级覆盖确认 → 移到空类别 → 占用目标拒绝 → 筛选后草稿仍在 → 校验再保存 → 修改后需复检。使用测试分类和文件进行覆盖/删除验收。

尚未包含普通结果导入、多文件/片段合并、整车平移、SEQ 强制例外、历史归档及运行图绘制。已执行测试与代码边界见 [开发状态](development_status.md)，接口见 [API 契约](api_contract.md)。


## 锁定表头、两级列车显示与独立标签页（2026-10-25）

已实现以下编辑交互，BaseTT 和普通 run 使用同一组件：

- 时刻表第一列车站横向锁定；车次号、日期、到达/出发（及可选股道/SEQ）为三行表头，整体纵向锁定。数据区在自己的滚动容器内横向/纵向滚动。
- “显示股道”和“显示SEQ”是两个独立开关，可只显示其中一项或同时显示。
- “列车选择”下拉复选确定初选范围，初选项默认显示；其下方、字段开关上方的“列车显示控制”表格可展开/收起，仅列出初选列车，用勾选进一步控制可见列车，提供全部显示/全部隐藏。移出初选后再加入的列车默认显示。两种筛选均不删除事件或丢弃隐藏草稿，也不把单纯显示变化视为时刻数据修改。
- “在新标签页中编辑”打开独立编辑页，保留完整车站/列车选择、二级显示表、股道/SEQ 控制、所属类别和校验保存。主界面暂收起同一编辑器。
- 独立页点击“Dock · 嵌回主界面”，回到原主界面相同对象并保留未保存修改和显示选择。若原窗口已关闭或无法响应，在当前标签页恢复主界面；主界面也提供“恢复到当前界面”。位置和版本已变化时，保留草稿并要求核对、复检。

跨标签页交接只暂存编辑快照（对象/版本/修改/显示选择），不是保存数据库或归档；交接失败时保留编辑页并提示。独立标签页刷新可恢复；关闭全部页签不承诺草稿恢复。内容经同源、对象和交接标识核对，服务端保存仍执行原有修订检查。


## 运行基准日保存与Excel导出（2026-10-25，已实现）

BaseTT/run 的编辑器提供可修改的“运行基准日”和“保存”。只有日期变化、没有单元格变化时也可保存；保存先校验当前完整对象，列出整体基准日与列车基准日变化，确认后一次事务提交。基准日重定保持事件时分秒、累计秒和日偏移，更新实际到发日期及列车基准日；若同时输入完整日期时刻，则按新基准日解析。版本和修改集（含日期）绑定校验凭证；日期变化不允许复用旧凭证，失败保持原数据。读取接口提供 arrival_datetime/departure_datetime，Excel导出写真实日期时刻，不带入1900年源日期。

基本图和run都有“导出”：默认基本图为TTT、LINE_INFO、NODE_INFO、MINIMUM_RUN_TIME四表合成一个xlsx；run默认仅TTT，可勾选有效基本图提供的基础表。允许逐表选择，不按页面车站/列车显示筛选删减导出数据；未保存修改需先保存。TTT使用现有五列节点标识及每车_A/_D/_G/_SEQ宽表，保留源表名（单一源表时），不推测缺失节点索引。

导出明确选择“是，覆盖所选表单”或“否，另存新文件”。覆盖时重新选择磁盘源Excel，确认文件和表单后，仅替换同名表单；未选工作表及其公式、图片等OOXML内容原样保留，并保持源工作簿1900/1904日期系统。目标缺少所选同名表单则拒绝，不能隐式覆写别的表；非标准/超限源工作簿拒绝。新文件由用户指定文件名和位置。

浏览器上传不提供原磁盘路径，所以不自动猜测、覆盖上传前文件。支持本地文件选择与写入API的浏览器由用户授权选择后直接写回；源文件在生成期间改变时拒绝覆盖，写失败中止提交。不支持直接写入时，明确下载合并后的工作簿，需用户手动替换原文件，不能把下载称为已覆盖。一般“保存”仅保存数据库工作状态；明确“导出覆盖”才会改变用户选定的磁盘文件。应用受管导入来源仍用于原始来源追溯，和编辑结果导出区分。

当前只支持xlsx。多日期同车次无法无损合成宽表、同站不同列车线路集合不一致、缺少NODE_IND/NODE_CODE等情形明确拒绝，不合并或猜测。通用统计、图片、比较和选中车次图形导出仍为后续范围。实现见 docs/api_contract.md 和 docs/schema_design.md。


## 时刻表显示排序（2026-10-25，已实现）

在“显示股道 / 显示SEQ”下方提供一行排序控制，基本图、run及独立编辑页共用：

- 车站排序：下行按LINE_IND升序，再按NODE_IND升序；上行两者均降序。相同站点只显示一次，多线路站按最小LINE_IND归组；缺少编号的项排在最后，已知排序键相同时保留源顺序。默认可选“原始顺序”。
- 列车到达排序：只能从当前勾选车站中选站，按该站到达时刻从早到晚排列完整列车列组。
- 列车出发排序：同上，按出发时刻排列。到达/出发两种模式互斥，最后一次选择生效；撤选排序车站会解除相应排序。
- 恢复原始顺序：还原关联源Excel中的车站行序、列车列序，解除两个时间排序。保留车站/列车勾选、二次隐藏、字段显示及全部草稿；不把数据库ID、名称字母序或NODE_IND当作源Excel顺序。

列车排序使用完整累计秒/跨日信息及当前草稿，按本节后的三级规则选取可用时刻，再统一按时间插入排序；同刻先按优先级，再保持源Excel列序。仅全部兜底均无时刻者置后。输入到发字段时不立即跳列，离开单元格后刷新排序，包括另一到发字段及邻站的修改。A/D/G/SEQ始终以同一train_id整体移动，显示开关只控制可见字段。

排序是视图状态，不改事件SEQ、日期、源文件或工作数据，不使已有校验结果失效，也不改变完整数据导出顺序。设置随页签草稿及新窗口/Dock交接保留，刷新可恢复。源文件缺失/损坏时编辑器仍可使用，恢复时明确提示按保留的来源记录回退。


## 线路筛选与紧凑到发列（2026-10-25）

筛选行按“线路选择 → 车站选择 → 列车选择”排列；“显示SEQ”下方的排序行按“车站排序 → 列车到达排序 → 列车出发排序 → 恢复原始顺序”排列。默认“所有线路”。选择一条线路后，自动选中该线路在当前对象中的全部车站；“车站选择”只列出此范围，可搜索、撤选和全选进一步微调。切回“所有线路”会重新全选当前对象的全部车站；线路本身没有本站时显示空结果，不补造访问。

线路按LINE_IND列出并显示名称。BaseTT使用自有LINE_INFO，run使用当前有效基本图的线路名称；事件中存在但未配有名称的线路仍用编号显示。共用站点在任一所属线路内均可选，单次只显示一行。指定单条线路时，上/下行按该线路的NODE_IND降/增序；所有线路时保留LINE_IND优先的排序规则。

切换线路与车站仅改变显示，保留所有待保存单元格、列车粗选与隐藏状态；撤去当前排序车站会解除列车时间排序。校验问题定位可切回所有线路以显示隐藏站。刷新、独立页和Dock交接保留线路与细选车站；旧草稿没有线路字段时按所有线路恢复。恢复原始顺序只还原当前筛选范围内的行列顺序，保留线路、车站和草稿。

到达/出发输入宽度由145px缩至72px（约一半），维持HH:MM:SS及完整日期时刻输入能力；股道/SEQ列保持原宽。首列与前三行继续锁定。校验、保存、导出始终使用完整对象，不因线路过滤缩减范围。


## 列车到发三级插入排序（2026-10-25）

三级为候选排序时刻的选取优先级，选定时刻后按早晚插入同一个列车序列，不把低优先级列车整组追加在高优先级之后。

1. 所选站有所选字段：到达排序取到达，出发排序取出发。
2. 所选字段缺失或无效，但该站另一字段可用：改用该站出发/到达时刻插入，适用于始发/终到列车。有效的00:00:00不能当作空值。
3. 列车未经过所选站（无此站访问事件）：按所选线路全部车站的NODE_SEQ_OF_LINE站序列表，从排序站位置向两侧逐步检索，采用第一个存在可用到发时刻的站点；该站仍优先取所选字段，再取另一字段。检索包括被显示筛选隐藏的站，找到后立即停止，不遍取所有站的最早时刻。

第3级按各线路自己的NODE_SEQ_OF_LINE站序距离向两侧检索，同距先较小站序。选择“所有线路”时只检索排序站所属线路；跨所属线路同距先小LINE_IND，再小NODE_SEQ_OF_LINE，不跳至无关线路。共享站保留每条线路各自的站序；站序缺失或重复不回退NODE_IND、Excel行序或名称排序。run读取有效基本图完整线路节点，再映射到自身事件node_id，因此隐藏站和没有本run访问的站仍保留检索位置。车站行的“上行/下行排序”继续按既有LINE_IND/NODE_IND规则，本次仅更正列车排序的第3级。

无可用候选时刻的列车留在末尾；该站确有访问但到发均为空/无效时也留在末尾，不当作“未经过”。同刻按第1→2→3优先级排序，同级保持原Excel列序；未排序尾部也保持原列序。到发时刻先按当前草稿解析为累计秒，保留完整日期/跨日偏移；非法草稿仍需通过保存校验修正。修改任一到发单元格后在失焦时重排，切换线路/排序站/基准日也重新取值。只调整显示顺序，不新增访问、不更改时刻/SEQ/源Excel或导出顺序。

### 四表预检显示车站名（2026-10-25）

涉及NODE_INFO或TTT车站行的错误/警告同时显示NODE_IND、NODE_NAME和可用中文站名，例如“NODE_IND=999 / NODE_NAME=Langfang / 站名=廊坊”。同路网节点索引冲突逐站给出来源位置；未通过解析或超过前200行预览的错误记录也保留原始行的站名及编号。表头/缺表等无对应车站的问题不显示虚构节点信息。刷新页面并重新执行四表预检即可生成新定位信息，原有错误判定和提交规则不变。

基本图或run时刻表中的“查看运行图”打开单线路绘图与基本图叠加，操作和资料不足排查见[运行图操作指南](train_diagram_guide.md)。

新导入在库内将每方向的到发线数组与正线号分开保存；导出仍为紧凑两列。股道校验包括上下行到发线及正线的合并去重集合，按LINE_IND与本站记录隔离到发场。运行图可展开车站股道，详见[运行图操作](train_diagram_guide.md)。

无正线的北京南/上海虹桥示例无需补造正线号；此前按旧规则失败的预检需重新发起。已有纯列表可直接读取为全到发线，导出仍省略/正线号。


2026-10-25补充：同一列车_SEQ必须为唯一、连续的正整数，但可从任意正整数开始（如5、6、7），可在Excel列内任意行排列（如7、5、6）。按SEQ数值识别访问先后，不按Excel行号或股道号推定。重复、非正数或真实中间断号仍阻断；NODE_SEQ_OF_LINE是独立线路站序字段，其原规则不因本次列车SEQ更正而改变。

_G错误定位原_G单元格及原值；SEQ检查使用所有原始有效_SEQ，不因_G或时刻错误剔除该编号。因而单独的股道错误不会制造假的SEQ断号。真实_SEQ问题定位原_SEQ单元格，并显示重复号或缺失范围；不自动重排表格或重编号。请重新预检此前任务。


## 股道缺列与修复
