## 独立对象与工作区

单一物理 DuckDB 中分别管理 BaseTT 与普通 run。基本图使用 base_tt_id/baseTT_no 与唯一 owner_category_id；run 使用 run_id/run_no 与批次归属。工作区成员按对象类型保存引用，不能把基本图伪装为 run。加载已存对象只添加成员关系，不复制源文件、不创建新的基本图或 run。

本级是否有物理基本图由存储归属决定，不由是否勾选工作区成员决定。当前工作视角按最近祖先解析；分类无图可回溯到研究员，run 从批次开始。清空工作区不会解除物理绑定，也不会把回溯图复制进本级。来源不存在则明确提示，不回用旧的可写绑定配置。

## 工作修改与确认快照

首次工作修改建立可持久恢复的工作副本，预览/分析读取有效工作值；历史查询只读确认快照。BaseTT 与 run 的归档各自显式确认，不隐式归档其他对象。基本图工作内容变化后，其实际继承范围内的绘图、轴、分析和比较缓存失效；下级自有图的范围保持独立。

基本图的存储位置编辑是共享分类归属变更，必须预览原、新范围并确认，不能通过某个 run 的归档或撤销回滚。普通 run 归档可以记录当时解析出的 base_tt_id/baseTT_no、内容修订和来源路径，作为历史追溯，不作为当前运行时任意绑定的覆盖字段。

历史对象的来源位置使用当时快照还是按当前分类显示，以及旧记录如何补齐独立基本图身份，按 D09 明确。依赖未归档基本图时是否允许归档、如何取得可重现基准按 D02 定稿；不能仅保存修订号就宣称完整旧内容可恢复。实验与对比仍要求有效基本图身份一致；不同研究员根无共享物理祖先时，不绕过该要求增加跨根绑定。

## 清空、删除与恢复

清空工作区仅移除成员，不删除实体、草稿、源文件或历史；未归档草稿的用户选项按 D03 定稿，未确认前不自动清理。BaseTT 的物理存储和回溯结果与工作区成员隔离。

基本图删除与 run 删除分开，前者的继承依赖/回退边界按 D08。分类删除须单列物理图，先移动或独立处置；不能用 run 的未分组选项使基本图失去存储类别。移动目标已占用按 D06 暂阻止，不能用归档覆盖规则替代移动确认。

受管文件先暂存并记录状态，数据库事务不能替代磁盘回滚；提交后清理旧独占文件，失败保持旧数据/位置/来源。已有旧基本图 run 的迁移须预览唯一存储位置、建立旧新 ID 对照并验证任务/文件/历史引用，具备备份和回退边界后再执行。本次未迁移或生成历史快照。


## 共用时刻表编辑与导航补充

导航树只显示实际存储在类别下的基本图，不为回溯结果创建条目；继承读取和工作/历史视角仍按独立服务解析，不能依赖当前树可见内容。

BaseTT 与 run 使用同一编辑界面，顶部显示真实直属类别和“编辑所属类别”，中部车站/列车下拉复选，下部单元格编辑及“校验”“保存修改”。输入草稿、校验通过、保存工作修改、确认归档是不同状态；筛选或翻页不能丢失草稿，校验不写正式内容，保存只写当前修改集且不自动覆盖历史确认内容。

对象切换或类别位置变更涉及未保存输入时，先明确保存/放弃/取消；不能静默搬移并沿用旧校验。共用界面不合并 BaseTT/run 身份与归档单元；有效基准/位置变化使相关校验与分析按规则失效。详细设计见 [共用编辑计划](../planAI/plan_timetable_editor.md)。
