# 运行图绘制与检查指南

更新：2026-10-27。当前为单线路基础运行图第一阶段；适用于独立基本图BaseTT及普通run，共用主界面和独立时刻表编辑页。

## 打开与操作

1. 在分类树选中实际存储的基本图，或批次下已导入TTT的run，打开其时刻表。
2. 点击“查看运行图”。窗口顶部显示当前对象、直属类别完整路径、运行基准日，以及实际有效基本图的名称、baseTT_no和真实存储类别。
3. 在“绘图线路”选择一条线路。默认优先使用编辑器当前选线；否则选择首条可绘线路。一次绘制一条线路，不直接解析用户Excel。
4. run可勾选“叠加有效基本图”，以实际回溯基本图作比较。基本图在叠加时用虚线；run按方向显示。基本图自身也可单独作图。
5. 展开“绘图车站”“绘图列车”进行搜索、复选或全选/清空；可点击列车“明细”加入对比并查看实际到发、SEQ、股道和源表行；已有选择保留。
6. 展开“车站股道信息与展开”，选择车站并点击“展开本站股道”；也可直接双击图中站名，重复操作收起。
7. 展开“设置时间范围”，输入完整开始/结束日期时刻，点击“应用时间范围”。跨日保持实际日期，午夜00:00:00是有效时刻。
8. 点击“返回时刻表”继续编辑。修改仍通过原编辑器“校验”“保存”提交，绘图窗口不保存时刻数据。

| 控制 | 操作 |
| --- | --- |
| 放大/缩小 | 以鼠标位置为中心：普通滚轮同步缩放X时间轴和Y车站轴，Ctrl+滚轮仅缩放X轴，Shift+滚轮仅缩放Y轴；也可点击按钮 |
| 平移 | 在图内拖动；图获得焦点后可用方向键 |
| 键盘缩放/复原 | +或-；Home恢复自动范围 |
| 站轴方向 | 勾选“逆序站轴”，仅翻转显示 |
| 高亮与明细 | 点击运行线选中一组；Ctrl+点击增选/取消；“所选列车时刻明细”显示全部已选组，也可在其中复选列车 |
| 悬停 | 显示实际到发端点/来源；在线段上提示真实起终站，不虚构中途时刻 |
| 股道展开/收起 | 双击站名，或展开股道信息面板选择车站；“收起全部股道”恢复合并车站线 |
| 复原 | Home图标或“恢复自动范围”恢复两轴；横向双箭头只恢复时间轴，纵向双箭头只恢复所选车站轴，另一轴范围保持不变 |
| 绘图高度 | 拖动图底部“拖动调整高度”横条；聚焦横条后用上下方向键每次调整40px，Home或双击恢复默认高度，End调到4000px；浏览器记住基础高度，股道展开另加所需高度 |
| 全屏 / Dock | 点击图右上角全屏图标；全屏时该按钮变为方框内旋转180°的斜箭头，提示“恢复嵌入 Dock 显示”，点击退出全屏并恢复原嵌入高度及视窗；Esc也可退出 |

| 刷新 | 重新读取对象、有效基本图、数据及样式；旧草稿上下文变化时须先回编辑器核对 |

绘图筛选独立于编辑器的初选列车和车站，默认包含所选线路上的全部有效列车/车站，以便比较整条线路。筛选隐藏不删除数据、不跨被隐藏车站补造新线段。详情可查看完整线路事件，表格保留真实空值。

## 绘图高度、全屏与范围工具

绘图右上角依次提供全屏/Dock、Home（两轴自动范围）、左右双箭头（仅时间轴）、上下双箭头（仅车站轴）。分轴复原不清除高亮或改变另一轴；仅车站轴复原也保留时间输入框中尚未应用的内容。

嵌入模式的基础绘图高度可在340—4000px之间拖动调整，单独展开的股道区域在此基础上增加所需像素。全屏将图本身铺满屏幕，筛选、缩放、运行线选择和当前范围保留；展开股道/刷新期间保留画布与全屏状态并显示加载提示。浏览器不支持或拒绝原生全屏时，自动采用页面内最大化；同一Dock按钮或Esc恢复嵌入。高度只记在当前浏览器，不写入时刻表数据。

## 保存当前视图与回看

在run运行图查看窗口点击“保存当前视图”，填写名称并点击“保存视图”。同一run下名称须唯一。保存成功后，分类树下该run新增“视图：名称”子节点；点击子节点或其右键“查看保存视图”即可打开。重启前后端后仍可回看，其他编辑标签页保存的视图会在主窗口重新获得焦点或手动刷新后出现。

保存内容包含：所选线路、基本图叠加开关、车站选择、列车显示选择、run与基本图各自的列车身份、高亮及明细选择、时间/车站视窗、逆序站轴、股道展开状态、时间输入、明细展开和绘图基础高度。基本图与run同车次分别记录，不相互替代；已隐藏但仍被选为明细/高亮的列车也保留。

视图同时保存本次绘图数据快照与样式，所以后续时刻表编辑、run覆盖或基本图绑定变化不会把原有图形或选车状态改掉。快照包含保存时显示或高亮的列车，保留完整原站轴及这些列车的原始访问；不保存未选列车。回看窗口明确显示名称和保存时间，可以继续筛选、缩放、逆序、高亮、多车明细以及保存为新的视图。线路和股道展开按保存时状态回看，需要其他线路或新的展开时，请从run重新打开当前运行图。

保存草稿预览的视图会保存该预览快照，仍不会提交时刻表草稿；正式时刻修改继续通过主编辑器校验保存。视图不自动进入全屏，打开后仍可使用全屏/Dock按钮。每个视图的JSON快照上限32 MB，超过时减少显示/高亮列车后再保存。

视图跟随run移动或取消分组，删除run时同步清理。视图记录存放在服务端数据库中，不依赖当前浏览器的缓存；启动后端时自动增加存储表。

## 多列车时刻明细对比

在“所选列车时刻明细”中可同时比较全部已选列车：Ctrl+点击运行线增选/取消，或展开“选择明细列车”逐项复选。点击某车次“明细”会将其加入现有选择并打开对比区，不清除其他已选列车；普通单击运行线仍切换为单选。可用“清空选择”清除全部高亮和明细选择。

表格按车站对齐，每个列车/方案占一组SEQ、到达、出发、股道、绘图占用和来源列。表头标明车次、基本图/run方案及列车基准日；同车次的不同方案分别展示。同一车站多次访问按第1次、第2次等分行保留，不按同名站或SEQ相同合并。没有对应访问时显示“未经过本站”/“无对应访问”，实际到发缺失仍显示“空”，午夜与跨日日期完整保留。列多时横向滚动，表头和车站列固定便于对比。

## 轴、时刻与方向规则

横轴使用相对当前对象运行基准日的累计秒；刻度显示HH:MM及跨日天偏移。整点小时线使用绿色2px加粗实线，半小时线使用同色同宽的虚线（8px实段、5px间隔），独立于自动分钟网格绘制，跨日仍按整点/半点显示。分钟线保持原有细线，不重复覆盖整点/半点；极端缩小时只保留抽稀后的整小时倍数线，避免过密。纵轴按有效基本图NODE_INFO.NODE_SEQ_OF_LINE站序排列，以相邻正向PASS→PASS主最小运行时间累计等效间距，并非实际公里数。共享站使用所选线路的站序。逆序显示沿用同一组坐标，不改用反向区间重新算轴。

列车按完整SEQ访问序列绘制，到达→出发为停站段，前站出发→下一访问到达为区间段。缺少必要到发、SEQ缺口、线路外访问均保留断点，不按Excel行序或过滤后的点顺序直接连线。真实时间倒置保留并用橙色虚线标示，不能通过重排时刻掩盖问题。方向根据SEQ访问在线路站序上的增减判断；单点/换向为方向未定并提示。密集站名通过标签避让和指引线显示，车站实际坐标不变。

第3级列车列排序已经更正为按每条线路的NODE_SEQ_OF_LINE向两侧检索最近可用站；同距先小LINE_IND再小站序，缺少/冲突站序不回退NODE_IND。此更正仅用于列车列排序，时刻表车站行的上/下行排序仍遵循既有LINE_IND/NODE_IND规则。

## 保存数据、草稿与叠加

无草稿时读取最新已保存工作数据。有未保存单元格或运行基准日修改时，绘图先用共用编辑校验生成只读预览，标题区域显示“预览未保存草稿”；非法数据阻止绘图并列出原因。打开图、筛选、改范围、预览不会更新数据库事件、日期、修订或源Excel。关闭图后草稿仍在原编辑器。

run叠加固定使用其实际回溯的有效BaseTT，不允许选择其他旁支图。当前要求run与基本图运行基准日相同，同名列车实例基准日也相同；不符合时关闭叠加即可查看run自身，不能静默挪动日期。图中两类方案共用相同站轴和时间基准。

## 资料不足与诊断

线路菜单标注“资料不足”时仍可选中查看具体原因，图不生成虚假的坐标。常见原因：没有有效基本图、NODE_SEQ_OF_LINE缺失/重复/不连续、有效节点少于两个、节点身份不一致、相邻有向PASS→PASS主时间缺失/重复/非正值，或当前对象无可绘时刻。不能用NODE_IND、Excel顺序、反向时间、备选最小时间或实际里程代替缺失资料。

“绘图提示”显示本次问题；“查看绘图日志”读取配置logs目录的log_plottraindiagram.md最后至多64KB。日志含时间、操作ID、对象/线路/有效BaseTT及问题。实际写入失败单独提示，不能把按钮点击当作日志已保存。草稿/旧修订冲突须返回编辑器重新核对。

## 样式文件

项目根diagram_styles.json提供默认样式。可设置down/up/unknown、base/base_dark、grid、highlight颜色，width、point_radius、font_size、grid_minutes、track_gap（单位5px，默认1）、track_yita_seconds（秒，默认1），以及train_styles[key]的color/width/dashed。颜色采用#RRGGBB，未知字段和越界值拒绝。列车key可在“样式配置”中查看。它只影响显示，不改列车身份或运行数据。

窗口约每4秒读取有效样式并重绘，保留当前缩放、时间范围和选择；也可点击“刷新图形数据和样式”。无效JSON/配置沿用本进程上次有效样式并提示，样式错误同步写入管理日志。

## 车站股道运用图（新格式已实现）

基本图NODE_INFO的DB_TRACKS/UB_TRACKS支持 `[10,11,12]`（无正线）或 `[5,6,7]/6`（6号正线兼到发线），有正线时在斜杠后填写，没正线时整个后缀省略。库内分别保存每方向到发线数组和可空正线整数；Excel导出仍为两列紧凑文本。UP_TRACKS为上行别名，两列同时提供必须分别核对到发线集合与正线号。旧预检任务需重新预检；纯列表直接视为全到发线，无须补造正线；空单元格未知，不自动推造股道。

展开面板先核对线路、站名、两方向到发线、正线和合并总集合。示例下行正线9、上行正线16、共用到发线10—15时，显示9—16共8条股道；若两方向正线都是9则共7条。只合并所选线路本站的记录，不跨线路或到发场，不从1开始补造编号。`[]/9`表示仅有正线；无正线的纯列表也可直接展开，正线显示“无”；只有未知或非法资料需要补充。

双击站名或使用面板展开后，显示N条股道线加上下两条到发边界。股道编号自下往上升序，真实编号不连续时仍等间距；正线以虚线及编号后的*标记。上边界为下行到达/上行出发，下边界为下行出发/上行到达。逆序车站轴不改变本站股道号顺序和上下边界含义。多站可同时展开，隐藏本站后不占用显示空间，恢复显示保留展开状态；收起不改筛选、视窗或数据。

停站列车设实际到达累计秒为A、出发为D、股道编号为k，显示进路按 `(A,到达边界) → (A+k×yita,第k股道) → (D−k×yita,第k股道) → (D,出发边界)` 绘制。k是真实编号，例如11，不是列表中的第几项。占用明细另列绘图起止时刻，原到发与_G保持原值；悬停计算点标示“用于绘图”。不同方案共用本站展开坐标，仍采用各自的到发/股道。

通过列车按到达与出发累计秒相同判定：到发边界直接连线，并在实际_G指定的股道水平线上添加一个通过点，不套用停站进路时间公式。_G为空或不能定位到所选线路股道时，以该线路上下行正线位置的中点绘制红色三角形，表示“股道未判定”，不采用默认1号或自动指定正线。两方向共用正线时标记位于该共用正线；缺少一方向正线时使用现有正线位置，两方向均无正线时放在展开区中心并提示。通过点、三角形均可悬停查看来源、选中列车；标记不回写时刻或_G。

到发缺失只画可确定的点和进出部分，不补造完整占用。计算起点晚于终点时提示并只保留实际到发点，不交换时间、不擅自补时；相等时保留零长占用。未定方向不猜上下到发边界；股道非空越界不能定位占用。停站列车空_G仅在真实集合含1时绘图采用1并警告，集合不含1则不画虚构1号或自动套用方向正线。所有本次绘图问题进入绘图日志，扩展面板也显示资源问题。

股道间距为track_gap×5像素，增减仅影响显示；进路系数track_yita_seconds采用累计秒，支持跨日。修改系数会自动重新生成占用几何并保留视窗；基础站序与PASS→PASS间距始终不变。验收截图见[股道占用叠加](qa/track-usage.jpg)。

正线兼作到发线：DB=[5,6,7]/6、UB=[5,6,8]/5时，只显示5、6、7、8四条股道线；5与6保留正线标记，并在到发线列表中出现。全部为到发线的北京南/上海虹桥示例使用纯列表即可。

列车_SEQ可从任意正整数起号，源表行序任意；绘图按SEQ实际访问顺序连接相邻编号，不按Excel行位置连接。导入/编辑_G采用本站各所属线路的资源OR校验，图中占用仍仅定位于所选线路集合；不能定位时提示并保留实际到发点，不额外画其他线路股道。


## 先修复股道再展开

股道不完整时，可回到共用编辑器点击“修复股道信息”，完成勾选和分配后校验、保存，再查看运行图。修复按所选线路/方向的本站资源分配，股道展开仍只显示当前所选线路的资源；本站另一线路合法编号不等于当前线路可显示的股道。详细规则、占用区间边界与限制见[股道修复指南](track_repair_guide.md)。

## 统一run分析工作区

run的运行图已纳入运行图分析、求解日志、延误分析三个独立折叠小节；新保存节点记录整个已读取分析工作区。旧运行图视图继续兼容，统一界面与延误口径、日志可视化接入详见[run分析指南](run_analysis_guide.md)。

## 运行图悬浮窗口与绘图列车排序

run分析工作区通过“查看运行图”打开独立的全窗口宽度悬浮对话框，保留三个折叠小节；“返回时刻表”或Esc关闭对话框并返回原时刻表。已保存视图、日志和延误节点使用同一窗口回看。

“绘图列车”选项按首字母X、G、T、K、D优先，再按车次的第一个连续数字段从小到大，最后基本图在前、run按run_no数值升序。同车次不同日期再按日期等稳定排列。其他首字母放在上述五类之后；不含数字的项放在该类型有数字的项之后。G2660/G2661等名称使用首个数字2660比较，忽略大小写和前导零。搜索保留排序，选择状态与实际运行线绘制顺序不变。数据集中的series.run_no提供方案编号；旧快照缺少此字段时，所属run使用已保存的object.run_no，不从用户自定义名称推测编号。
